# 神经塔防（VEP 注意力对战）设计与实现计划

## 1. 概要

在空目录 `/home/thuan/Documents/Hackwell/game` 从零搭建一个可玩的浏览器 2D 对战原型：双方各守一个据点，玩家把注意力锁定在底部某张闪烁卡牌上，持续 1.5 秒后该卡牌对应的单位被派出，沿中间通路冲向敌方据点。单位在途中与敌方单位对撞交换伤害，抵达敌方据点造成一次伤害后消失；据点 HP 先归零的一方失败。

现阶段不接入 EEG：**长按鼠标（或按住键盘键）1.5 秒 = 模拟一次稳定的 VEP 激活信号**，用来验证“锁定注意力 → 出兵”的操作手感与全部游戏逻辑。EEG 模块后续只替换输入层。

交付物：可直接 `npm run dev` 运行的双人同屏原型。

## 2. 现状与约束

- 仓库为空，无任何既有代码、依赖或约定，需完整脚手架。
- 环境：Node v26.10.0 / npm 12.1.0 / Python 3.14（本阶段用不到）；npm 源可用。
- 采用最新稳定依赖：`pixi.js@^8.22.0`、`vite@^8.3.5`、`typescript@~5.9`。
- 参考草图解读（按 [image] 中的 UI 标注）：
  - 单屏左右分屏，深黑背景；左右各一个据点，标注 `HP: 10`。
  - 中间一条横向通路，双方单位相向移动；背景有 2 个低对比度的三角形“山”装饰。
  - 底部左右各 3 张角色卡，卡头显示 `生命 / 伤害`，每张卡闪烁频率不同（5–15 Hz）。
  - 单位相遇：双方同时扣血，未阵亡者后撤再继续前进；据点承受 10 次伤害后被摧毁。
  - 玩家激活卡牌 → 生成单位 → 向对方据点移动。
- 已与用户确认的决策：
  1. 技术栈：Web + PixiJS。
  2. EEG：独立模块负责，现阶段不关心数据；用鼠标点击类操作替代 VEP 激活。
  3. 布局：单屏左右分屏。
  4. 资源模型：**无冷却、无能量条；长按 1.5 秒出兵**，模拟 VEP 需持续 1.5 秒稳定注意力。
  5. 攻城：单位抵达敌方据点**打一下就消失**。

## 3. 游戏设计

### 3.1 核心循环

```
观察敌方出兵 → 选择自己的一张卡（闪烁频率）→ 长按 1.5s 锁定注意力
→ 单位出兵 → 单位在通路对撞/推进 → 抵达据点造成一次伤害
→ 据点 HP 归零 → 胜利/失败 → 按 R 重开
```

“注意力即资源”的体现：出兵成本是**时间**——必须把注意力持续压在同一个刺激上 1.5 秒，中途切换会清零。持续按住同一张卡会每 1.5 秒稳定产出 1 个单位。接入 EEG 后，把“鼠标长按”换成“分类器连续 1.5 秒判定为同一频率”。

### 3.2 规则与数值（全部集中在 `src/config.ts`，便于调参）

| 项目 | 数值 |
| --- | --- |
| 设计分辨率 | 1280 × 720（等比缩放、黑边居中） |
| 据点 HP | 10 / 10 |
| 出兵锁定时间 | 1.5 s |
| 单位移动速度 | 100 px/s |
| 单位对撞判定距离 | 36 px |
| 对撞交换间隔 | 0.6 s（双方同时结算伤害） |
| 对撞后撤距离 | 16 px |
| 抵达据点 | 造成自身 `伤害` 后立即消失 |
| 卡牌 1 | 生命 1 · 伤害 1 |
| 卡牌 2 | 生命 2 · 伤害 1 |
| 卡牌 3 | 生命 2 · 伤害 2 |
| 闪烁频率（P1 低频段） | 5.0 / 6.67 / 8.57 Hz |
| 闪烁频率（P2 高频段） | 10.0 / 12.0 / 15.0 Hz |

说明：
- 频率按 60 fps 取整友好值（5Hz=6帧亮/6帧灭，10Hz=3/3，15Hz=2/2；6.67、8.57 用时间累加器实现平均频率）。两方分属不同频段，为后期同屏双人采集降低串扰。
- 单位数值沿用草图的 3 档卡牌；据点被 1 伤害单位蚕食时需 10 次命中，2 伤害单位需 5 次，攻防节奏约为 20–40 秒一局。

### 3.3 操作（现阶段）

- **P1**：按住鼠标指针悬停在左侧卡牌上 1.5 秒；或按住键盘 `1`/`2`/`3`。
- **P2**：按住鼠标指针悬停在右侧卡牌上 1.5 秒；或按住键盘 `7`/`8`/`9`。
- 多点触控/多鼠标：输入层按 `pointerId` 区分，支持两个人各用一只鼠标；单鼠标演示时用键盘替代。
- 松开指针或切换卡牌 → 该玩家当前充能清零；充能进度显示在卡牌底部进度条 + 描边提亮。
- `F` 切换闪烁开关（长时间盯屏护眼），`D` 切换频率调试标签，`R` 重开。
- 倒计时 3 秒后才可出兵；结算界面禁用出兵输入。

### 3.4 界面布局（1280 × 720）

- 背景：近黑 `#0E0F12`；顶部两座“山”用低透明度折线绘制（纯装饰）。
- 左据点：`x=120, y=150, w=150, h=180`；右据点：`x=1010, y=150, w=150, h=180`；上方文字 `P1 据点  HP 10` / `P2 据点  HP 10` + 细血条。
- 通路：`y=376`，从 `x=270` 到 `x=1010` 的一条细线。
- 单位：圆角竖块 16 × 30，带 2px 描边；单位头顶用小方块显示剩余生命（1–2 格）。
- 出兵点：P1 `x=292`，P2 `x=988`；据点受击线：P1 单位 `x >= 1010`，P2 单位 `x <= 270`。
- 卡牌：`150 × 126`，间距 22，卡头上方 26px 高的统计条（`生命 2 · 伤害 1`）。
  - P1 三张：`x=120 / 292 / 464`；P2 三张：`x=668 / 840 / 1012`；卡牌区 `y=500`，统计条 `y=474`。
  - 卡面填充斜线纹理（Graphics 线条），主色块按频率亮/灭闪烁。
  - 卡牌底部 5px 充能条；完成时卡牌短促闪白并触发轻微震屏。
- 底部角落小字提示按住键位；结算时中央大字 + `按 R 重新开始`。
- 相机抖动只作用于“战场层”（背景山、据点、通路、单位、飘字）；**卡牌刺激区固定不动**，避免闪烁刺激位移影响后续 SSVEP。

### 3.5 视觉风格

- 低饱和配色（`src/render/palette.ts` 统一管理）：
  - 背景 `#0E0F12`，面板 `#1A1C20`；
  - P1 钢蓝 `#5C7A93`（描边 `#8FA9BD`），P2 砖红 `#96635F`（描边 `#C0968F`）；
  - 文字/描边暖灰 `#D9D5CB`；装饰山 `#2A2C30`。
- 全部用 `Graphics` 色块、圆角矩形、线段、文字绘制，无任何图片资源。
- 闪烁的“亮态”使用低饱和主色，“灭态”使用近黑暗色，保持明度对比但饱和度低。

### 3.6 打击反馈

- 相机抖动（trauma 模型：`offset = maxOffset * trauma² * 噪声`，trauma 随时间线性衰减），强度：
  - 出兵 0.06 / 对撞交换 0.1 / 单位阵亡 0.18 / 据点受击 0.3 / 据点摧毁 0.6。
- 据点受击：据点描边闪白 + 全屏极低透明度白闪（α≈0.12）。
- 单位阵亡：原地扩散圆环淡出。
- 伤害飘字：`-1` / `-2` 小号暖灰文字上浮淡出。
- 所有特效轻量、无粒子系统。

## 4. 技术方案

### 4.1 技术栈

Vite + TypeScript + PixiJS v8，无框架、无外部素材。Pixi v8 API：`Application.init`、`Graphics` 链式绘制、`Text` 新构造参数、`eventMode='static'`。

### 4.2 目录结构

```
game/
├─ index.html                 # 深色页面容器 + 入口
├─ package.json               # scripts: dev/build/preview/typecheck
├─ tsconfig.json
├─ vite.config.ts
└─ src/
   ├─ main.ts                 # Application 初始化、等比缩放根容器、主循环
   ├─ config.ts               # 全部数值/频率/布局/配色引用
   ├─ game/
   │  ├─ types.ts             # PlayerId / Unit / CardState / GameEvent 等类型
   │  ├─ GameState.ts         # 纯逻辑：出兵、移动、对撞、攻城、胜负（不含渲染）
   │  └─ InputManager.ts      # 长按 1.5s → 出兵；多指针 + 键盘兜底；维护充能进度
   └─ render/
      ├─ palette.ts           # 低饱和色板
      ├─ Scene.ts             # 分层场景搭建 + 每帧状态同步
      ├─ CardView.ts          # 卡牌外观、斜线纹理、闪烁、充能条
      ├─ UnitView.ts          # 单位色块 + 生命格 + 飘字/圆环特效
      ├─ CameraShake.ts       # trauma 抖动
      └─ Overlay.ts           # 倒计时 / 结算 / 操作提示
```

### 4.3 关键实现

1. **主循环与确定性**：`app.ticker` 累积 `deltaMS`，以固定步长 `1/60 s` 推进 `GameState.update(dt)`（单帧最多补 6 步，防止切后台后跳帧），渲染层每帧同步一次。`GameState` 不依赖 Pixi，方便后续单测/调参。
2. **等比缩放**：根容器固定 1280×720，窗口变化时 `scale = min(w/1280, h/720)` 并居中，监听 `resize`。
3. **分层**：`bgLayer`（背景、山）→ `battleLayer`（据点、通路、单位、飘字，承受抖动）→ `cardLayer`（卡牌，不抖动）→ `uiLayer`（提示、倒计时、结算）。
4. **闪烁**：`CardView` 内维护时间累加器 `t += dt`，`on = Math.floor(t * f * 2) % 2 === 0`（50% 占空比），每帧切换填充色；`F` 关闭时固定亮态。
5. **长按充能（模拟 VEP）**：`InputManager` 记录每个激活源（pointerId 或键盘键）绑定的 `{player, slot, elapsed}`；每帧 `elapsed += dt`；`elapsed >= 1.5` 时调用 `game.spawn(player, slot)` 并把 `elapsed` 减去 1.5（持续按住则每 1.5s 稳定出 1 个）；松开/离开/失焦立刻清零；同一玩家只保留一个激活源（模拟单一注视点）。渲染层读取 `getCharges()` 画进度。
6. **战斗结算**（`GameState.update`，每固定步）：
   - 每个单位按朝向匀速移动；同侧单位互不碰撞。
   - 扫描异侧单位对，间距 `< 36px` 且各自攻击冷却已归零 → 同时结算 `伤害`，各后撤 16px（限制在通路内），进入 0.6s 冷却；HP ≤ 0 的标记阵亡并移除。
   - 单位越过受击线 → 对敌方据点扣自身 `伤害`、发出 `baseHit` 事件、本单位立即移除。
   - 据点 HP ≤ 0 → 进入 `gameover` 并记录胜方；闪烁停止、输入禁用。
7. **事件与反馈**：`GameState` 每步导出事件数组（`spawn / exchange / death / baseHit / baseDestroyed / gameOver`），`Scene` 消费后触发震屏、闪光、飘字、圆环并清空。
8. **相机抖动**：`CameraShake` 维护 `trauma`，每次 `addTrauma()` 叠加并 clamp 到 1；每帧 `trauma -= decay * dt`，位移用多频正弦噪声（随机相位）+ `trauma²`，仅作用于 `battleLayer`。
9. **初始化流程**：`main.ts` 创建 App → 构建 Scene → 构建 GameState（倒计时 3s）→ 绑定 InputManager → `ticker` 驱动。`index.html` 设置 `body` 黑底、`margin:0`、隐藏滚动条。

## 5. 假设与决策

1. 单位对撞按草图实现为“双方同时扣血 + 后撤再继续”，但阵亡者不再复活；每次对撞按 `0.6s` 冷却，避免每帧重复结算。
2. “打一下就消失”按用户确认实现：单位到达敌方据点造成一次 `伤害` 后消失，不自伤、不后撤。
3. 长按完成一次出兵后若仍按住，会继续充能并每 1.5s 再产出一个单位（连续注视的自然结果）；中途松开或换卡清零。
4. 两方 3 张卡的属性完全对称（生命/伤害相同），差异只体现在频率；后续可扩展为赛前选卡。
5. 同屏双人输入：优先支持多指针（两只鼠标/触屏多点），并提供键盘按键兜底，避免单鼠标无法双人操作。
6. 闪烁频率是视觉演示值与未来 SSVEP 刺激参数；本阶段不做分类器，频率仅用于外观与调试标签。
7. 不做音效、不做存档、不做联机；不做 PNG/图片素材，全部 Graphics 绘制。
8. 语言：界面中文，简短单位/统计标签；字体使用系统字体栈（`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`），不下载字体资源。

## 7. 验证方式

- `npm run dev` 后在浏览器逐项验证：
  1. 按住左侧卡牌 1.5 秒恰好生成 1 个 P1 单位；不足 1.5 秒松开不出兵；换卡清零；持续按住每 1.5 秒出 1 个。
  2. P2 卡牌与键盘 `7/8/9` 同样生效；P1 键 `1/2/3` 生效；两方互不影响。
  3. 单位按朝向匀速移动，同侧重叠不干扰；异侧相遇同时扣血、后撤、冷却后继续。
  4. 单位抵达敌方据点使 `HP` 按 `伤害` 减少并立即消失；据点 HP 归零触发结算，输入禁用。
  5. 抖动只发生在战场层，卡牌区域不发生位移；受击闪光、阵亡圆环、飘字按预期出现。
  6. 窗口缩放后画面等比居中、无拉伸变形；`F` 关闭闪烁、`D` 显示 `xx Hz` 标签、`R` 重开。
- `npm run build` 成功产出静态包；构建产物可 `npm run preview` 运行。
- 可用浏览器自动化截图核对布局与颜色，再手动打一局验证节奏。

## 8. 后续 EEG 接入点（本阶段不实现）

- `GameState.spawn(player, slot)` 与 `InputManager.getCharges()` 是唯一耦合点：用 EEG 模块（独立进程，WebSocket/SSE）推送“当前锁定的 `(player, slot)` 与置信度”替换指针输入，连续 1.5 秒判定一致即出兵。
- 频率表集中在 `config.ts`，刺激区已与震屏隔离，可直接用于真实 SSVEP 实验；若采集端需要更高频精度，可把闪烁切换到固定帧计数/高刷显示器。
- 采集端可按频段区分双方，降低同屏双人串扰。

## 9. 风险

- 单屏双人同看全部刺激，真实 SSVEP 下存在串扰；已用“双频段分配 + 刺激区不动”做前置缓解，最终以采集端验证。
- 15 Hz 闪烁可能引起视觉疲劳，提供 `F` 关闭与低饱和配色；比赛演示建议先短时使用。
- 单鼠标无法双人同时操作，依赖双鼠标或多点触屏；演示前确认输入设备，必要时用键盘兜底（已有）。
